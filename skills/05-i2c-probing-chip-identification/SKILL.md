# I2C 스캔과 칩 식별

## 1. 스캔 전에
- 주소 형식(7-bit/8-bit)을 펌웨어에서 확인합니다(03). 이 FX2 펌웨어는 7-bit.
- **칩이 꺼져 있으면 응답하지 않습니다.** 처음 스캔에서는 상시 전원인 칩(CX25843 0x44, EEPROM 0x50)만 보였습니다.
  Windows 드라이버의 GPIO 순서(04)를 재현한 뒤 다시 스캔합니다.

## 2. 스캔
쓰기 0바이트 프로브 대신 "레지스터 0 읽기"(`09 01 01 addr 00`)를 씁니다. 상태 8 = ACK.
```python
found = [a for a in range(0x08, 0x78) if cmd([0x09, 1, 1, a, 0x00])[0] == 8]
```
| 단계 | 보인 주소 |
|---|---|
| 펌웨어만 | 0x44 (CX25843), 0x50 (EEPROM) |
| PD6=1, PD1=1 | + 0x61 (튜너) |
| PD7 리셋 펄스 | + 0x59 (복조기) |

EEPROM 0x50의 첫 바이트 `C0 6C 1C C9 04`는 FX2 "C0 부트" 형식(VID/PID만 저장)입니다.

## 3. 주소별 후보와 확인 방법
| 주소 (7-bit) | 흔한 후보 | 확인 방법 |
|---|---|---|
| 0x59 / 0x0e | LGDT3305, LGDT3306A, LGDT3304 | 16-bit 레지스터 주소 `[hi lo]` 읽기가 되면 LG 계열 |
| 0x61 / 0x60 | XC5000, TDA18271, MxL5007T, PLL 튜너 | 아래 ID 레지스터 |
| 0x44 | CX25840/3/5 | |

## 4. 커널 드라이버의 probe 절차를 그대로 재현
커널 소스 attach 함수의 칩 확인 로직이 가장 믿을 만한 판별 기준입니다.

- **lgdt3306a_attach**: `reg0 & 0x74 == 0x74` → 이 장치는 0x54라 **아님**
- **lgdt3305_attach**: `GEN_CTRL_2(0x0001) != 0`, 0x0808에 0x80을 쓰고 다시 읽어 0x80 → 0x00으로 복구
  → 통과 → **LGDT3304/3305**. 3304와 3305는 Windows 초기화 테이블과 비교해서 3304로 확정(04)
- **XC5000**: `[00 08]` 쓰고 2바이트 읽기 → `0x2000` = `XC_PRODUCT_ID_FW_NOT_LOADED`
  (펌웨어를 올리면 0x1388). TDA18271(id 0x83/0x84)이나 MxL5007T(`fb d9`)는 해당 없음

## 5. 안전 수칙
- probe는 **읽기 위주**로 하고, 커널 드라이버와 같은 테스트 쓰기만 합니다. 쓴 값은 원래대로 되돌립니다.
- 모르는 칩의 레지스터에 함부로 쓰지 않습니다. EEPROM(0x50)에는 절대 쓰지 않습니다(부트 정보가 들어 있음).
- GPIO는 Windows 드라이버가 실제로 쓰는 비트만 건드립니다.
